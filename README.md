# Морской маршрут: учёт перевозок и BI на телефоне

Учебный проект. Вымышленная компания организует контейнерные перевозки: у неё нет своих судов, услуги заказываются у перевозчиков и подрядчиков. Все компании и данные вымышлены.

**Начните со [сопроводительной записки](docs/handover.md):** что сделано по ТЗ, как проверить за 10 минут, какие решения принимались самостоятельно и каковы границы первой версии.

Два интерфейса и одна цепочка данных:

- **Веб-приложение менеджера.** Ввод и изменение перевозок: клиент, груз и контейнеры, маршрут, сроки, доходы, расходы и оплаты. Неполные сведения можно сохранять и дополнять позже. Все изменения пишутся в базу, видна история «кто, когда, что».
- **Мобильная аналитика руководителя (PWA).** Три экрана отвечают на три вопроса, и в каждом есть интерактивные графики (нажатие открывает перевозки за ними; на «Сегодня» сверху заказы по дням с прогнозом). Три вопроса: **«Что требует внимания?»**, **«Что приносит прибыль?»**, **«Что изменилось?»**. У каждой цифры есть переход до конкретных перевозок, пояснение (что считаем, за какой период, чего в цифре нет) и отметка «данные на HH:MM».

## Быстрый запуск

Нужен [Node.js](https://nodejs.org) версии 20 или новее (проверено на 24).

```bash
git clone https://github.com/MarinaZakharova4344/sea-route.git
cd sea-route
npm install
cp .env.example .env
npm run db:seed
npm run dev
```

Откройте `http://localhost:3000`. Команда `db:seed` создаёт базу `data/sea-route.db` и загружает демонстрационные данные.

> На Windows вместо `cp` в PowerShell: `Copy-Item .env.example .env`.
>
> Компилятор C++ не нужен: база SQLite (`better-sqlite3`) подключается в готовом виде. Для этого в проекте лежит файл `.npmrc` с `ignore-scripts=true`, не удаляйте его.

### Реальные пользователи

Демонстрационные учётные записи нужны только для показа. Для работы заведите настоящих сотрудников (команды выполняются на сервере, где лежит база):

```bash
npm run db:migrate                                           # пустая база без демо-данных
npm run users -- add anna@company.ru "Анна Смирнова" manager  # пароль создаётся случайный и показывается один раз

npm run users -- disable anna@company.ru                      # сотрудник ушёл: вход закрыт, открытые сессии перестают работать сразу
npm run users -- list
```

Единственного руководителя отключить нельзя. Если в базе остались демо-записи, отключите их (`disable ivan@searoute.test` и т. д.).

### Демонстрационные данные

58 перевозок, 9 клиентов, 6 направлений. Данные построены от «сегодняшнего» дня, поэтому в любой день запуска в них есть опоздания, просроченные оплаты, перевозки без обновлений и неполные данные. Среди клиентов специально заложены:

- **ООО «Рассвет»** с самым большим оборотом, но маржей около 3,5 % и множеством проблем («выглядит лучше, чем работает»);
- **ТД «Север»** и **Гранит Строй**: небольшие, но выгодные и спокойные клиенты;
- перевозки с перерасходом, внеплановыми расходами, неполными данными, отменённая перевозка с расходами.

Загрузить данные заново: `npm run db:seed`. Крупный набор для показа графиков (около 960 перевозок за четыре месяца): `npm run db:seed:large`. Зафиксировать дату отсчёта: `SEED_TODAY=2026-10-20 npm run db:seed` (в PowerShell: `$env:SEED_TODAY="2026-10-20"; npm run db:seed`).

## Рабочая версия и установка на телефон (PWA)

```bash
npm run build
npm start
```

Не запускайте `npm run build`, пока работает `npm run dev`: обе команды пишут в одну папку, и страницы перестают загружаться.

- **Установка на компьютере.** Откройте `http://localhost:3000` в Chrome или Edge (кнопка «Установить» сразу запускает установку; в Яндекс.Браузере установка идёт через его меню, и кнопка только подсказывает это): сверху появится окно «Установить “Морской маршрут”?» с кнопками «Установить» и «Позже» (после «Позже» оно не показывается до следующего захода). В шапке всегда есть кнопка «Установить», пока приложение не установлено: если браузер сам не предлагает установку, она подсказывает, как установить вручную. Когда приложение установлено или открыто как приложение, окно и кнопка не показываются.
- **На телефоне установка и работа без связи требуют https**: по обычному адресу `http://192.168…` браузер её не предлагает. Для проверки нужен защищённый адрес, например временный туннель (Cloudflare Tunnel, ngrok) до порта 3000. На iPhone установка делается через Safari: «Поделиться» → «На экран Домой».
- **Без связи с сервером** приложение показывает последние открытые страницы с плашкой «Нет связи с сервером. Показаны данные, загруженные в …» (проверка каждые 15 секунд). При запуске на `localhost` отключение интернета на это не влияет, нужно остановить сервер. Менять данные без связи нельзя (в ТЗ это не требуется).
- Просто посмотреть с телефона в режиме разработки: телефон в той же Wi-Fi сети, адрес `http://<IP компьютера>:3000` (IP показывает `ipconfig`). Режим разработки на iPhone может показывать красную плашку разработчика, в рабочей версии её нет.

## Эксплуатация

Если приложением пользуются каждый день, а не только смотрят демонстрацию:

- **Резервные копии.** Вся работа лежит в одном файле базы. `npm run db:backup` делает согласованную копию (даже при работающем приложении) в папку `backups/` и хранит последние 14 (`-- --keep 30`, чтобы изменить). Запускайте раз в сутки по расписанию (планировщик заданий или cron). Восстановление: остановить приложение, заменить `data/sea-route.db` нужной копией, запустить.
- **Пользователи.** Заведение, смена пароля, отключение ушедшего сотрудника: `npm run users` (см. раздел «Реальные пользователи» выше).
- **Проверка работоспособности.** `GET /api/health` отвечает `{"status":"ok"}`, если приложение запущено и база отвечает (для мониторинга).
- **Часовой пояс.** Переменная `APP_TIMEZONE` (по умолчанию `Europe/Moscow`) определяет, какой день считается «сегодняшним».
- **Защита входа.** После 5 неверных паролей блокируется пара «адрес + e-mail» на 15 минут, поэтому посторонний не может закрыть вход руководителю. Адрес клиента приложение берёт из заголовка `X-Forwarded-For`, который передаёт прокси; без прокси адрес неизвестен, и считается только по e-mail (до 10 попыток).
- **Работа по https.** Если приложение стоит за прокси или туннелем с https, кука сессии получает флаг `Secure` автоматически.

## Тесты

```bash
npm test          # 116 автоматических проверок
npm run typecheck # проверка типов
```

Что проверяют тесты:

- **Расчёты:** маржа «факт, иначе план», «предварительно / окончательно», задержка, перерасход, просрочка оплаты, актуальность, границы порогов.
- **Аналитика:** итоги по клиентам и направлениям на числах, проверяемых вручную, разложение изменения маржи, периоды и их границы.
- **Права и безопасность:** вход, 401 и 403, подделанный и просроченный токен, смена роли «на лету», защита от запросов с чужого сайта, руководитель не может менять данные, менеджер не видит аналитику.
- **Нагрузка и случайные операции:** 3 000 перевозок за два года и 5 000 случайных операций менеджеров со сверкой цифр руководителя с пересчётом по сырым данным.
- **Одновременная правка, пользователи, секрет сессий, резервные копии.**
- **Правила перевозок:** неполные данные, согласованность дат и статусов, история изменений, финансовое закрытие и повторное открытие, сценарий 10 000 → 2 800 → 2 300 → окончательно.
- **Работа без связи:** логика service worker в изолированной среде.

## Настройки

Файл `.env` (образец `.env.example`):

| Переменная | Что значит |
|---|---|
| `SESSION_SECRET` | Секрет для подписи сессий: длинная случайная строка (не короче 32 символов). Если оставить образец из `.env.example` или не задать, в рабочей версии используется временный случайный секрет (после перезапуска все входят заново) и пишется предупреждение |
| `DATABASE_PATH` | Путь к файлу базы (по умолчанию `data/sea-route.db`) |
| `APP_TIMEZONE` | Часовой пояс компании (по умолчанию `Europe/Moscow`): от него зависит, какой день считается «сегодняшним» |

Пороги «требует внимания» (опоздание 2 дня, перерасход 10 %, нет обновлений 5 дней) и период обновления аналитики (5 минут) лежат в таблице `settings` базы данных.

## Известные ограничения

Полный список: [docs/calculations.md](docs/calculations.md#5-известные-ограничения). Главное:

- маржа валовая по перевозкам, без общих расходов компании и налогов;
- период перевозки определяется по дате доставки;
- аналитика отстаёт от правок менеджера до 5 минут (или до нажатия «Обновить»);
- без интернета данные только читаются;
- пороги (2 дня, 10 %, 5 дней) согласованы как стартовые настройки и меняются в таблице `settings`.
