# Морской маршрут: учёт перевозок и BI на телефоне

Учебный проект. Вымышленная компания организует контейнерные перевозки: у неё нет своих судов, услуги заказываются у перевозчиков и подрядчиков. Все компании и данные вымышлены.

Два интерфейса и одна цепочка данных:

- **Веб-приложение менеджера.** Ввод и изменение перевозок: клиент, груз и контейнеры, маршрут, сроки, доходы, расходы и оплаты. Неполные сведения можно сохранять и дополнять позже. Все изменения пишутся в базу, видна история «кто, когда, что».
- **Мобильная аналитика руководителя (PWA).** Три экрана отвечают на три вопроса: **«Что требует внимания?»**, **«Что приносит прибыль?»**, **«Что изменилось?»**. У каждой цифры есть переход до конкретных перевозок, пояснение (что считаем, за какой период, чего в цифре нет) и отметка «данные на HH:MM».

## Быстрый запуск

Нужен [Node.js](https://nodejs.org) версии 20 или новее (проверено на 24).

```bash
git clone https://github.com/MarinaZakharova4344/sea-route.git
cd sea-route
npm install
cp .env.example .env
npm run db:seed
npm run dev
```

Откройте `http://localhost:3000`. Команда `db:seed` создаёт базу `data/sea-route.db` и загружает демонстрационные данные.

> На Windows вместо `cp` в PowerShell: `Copy-Item .env.example .env`.
>
> Компилятор C++ не нужен: база SQLite (`better-sqlite3`) подключается в готовом виде. Для этого в проекте лежит файл `.npmrc` с `ignore-scripts=true`, не удаляйте его.

### Демонстрационные данные

58 перевозок, 9 клиентов, 6 направлений. Данные построены от «сегодняшнего» дня, поэтому в любой день запуска в них есть опоздания, просроченные оплаты, перевозки без обновлений и неполные данные. Среди клиентов специально заложены:

- **ООО «Рассвет»** с самым большим оборотом, но маржей около 3,5 % и множеством проблем («выглядит лучше, чем работает»);
- **ТД «Север»** и **Гранит Строй**: небольшие, но выгодные и спокойные клиенты;
- перевозки с перерасходом, внеплановыми расходами, неполными данными, отменённая перевозка с расходами.

Загрузить данные заново: `npm run db:seed`. Зафиксировать дату отсчёта: `SEED_TODAY=2026-10-20 npm run db:seed` (в PowerShell: `$env:SEED_TODAY="2026-10-20"; npm run db:seed`).

## Рабочая версия и установка на телефон (PWA)

```bash
npm run build
npm start
```

Не запускайте `npm run build`, пока работает `npm run dev`: обе команды пишут в одну папку, и страницы перестают загружаться.

- **Установка на компьютере.** Откройте `http://localhost:3000` в Chrome или Яндекс.Браузере: в адресной строке появится значок установки (в шапке есть кнопка «Установить»).
- **На телефоне установка и работа без связи требуют https**: по обычному адресу `http://192.168…` браузер её не предлагает. Для проверки нужен защищённый адрес, например временный туннель (Cloudflare Tunnel, ngrok) до порта 3000. На iPhone установка делается через Safari: «Поделиться» → «На экран Домой».
- **Без интернета** приложение показывает последние открытые страницы с плашкой «Нет связи… Показаны данные, загруженные в …». Менять данные без связи нельзя (в ТЗ это не требуется).
- Просто посмотреть с телефона в режиме разработки: телефон в той же Wi-Fi сети, адрес `http://<IP компьютера>:3000` (IP показывает `ipconfig`). Режим разработки на iPhone может показывать красную плашку разработчика, в рабочей версии её нет.

## Тесты

```bash
npm test          # 116 автоматических проверок
npm run typecheck # проверка типов
```

Что проверяют тесты:

- **Расчёты:** маржа «факт, иначе план», «предварительно / окончательно», задержка, перерасход, просрочка оплаты, актуальность, границы порогов.
- **Аналитика:** итоги по клиентам и направлениям на числах, проверяемых вручную, разложение изменения маржи, периоды и их границы.
- **Права и безопасность:** вход, 401 и 403, подделанный и просроченный токен, смена роли «на лету», защита от запросов с чужого сайта, руководитель не может менять данные, менеджер не видит аналитику.
- **Правила перевозок:** неполные данные, согласованность дат и статусов, история изменений, финансовое закрытие и повторное открытие, сценарий 10 000 → 2 800 → 2 300 → окончательно.
- **Работа без связи:** логика service worker в изолированной среде.

## Настройки

Файл `.env` (образец `.env.example`):

| Переменная | Что значит |
|---|---|
| `SESSION_SECRET` | Секрет для подписи сессий. В рабочей версии обязателен: замените на длинную случайную строку |
| `DATABASE_PATH` | Путь к файлу базы (по умолчанию `data/sea-route.db`) |

Пороги «требует внимания» (опоздание 2 дня, перерасход 10 %, нет обновлений 5 дней) и период обновления аналитики (5 минут) лежат в таблице `settings` базы данных.

## Известные ограничения

Полный список: [docs/calculations.md](docs/calculations.md#5-известные-ограничения). Главное:

- маржа валовая по перевозкам, без общих расходов компании и налогов;
- период перевозки определяется по дате доставки;
- аналитика отстаёт от правок менеджера до 5 минут (или до нажатия «Обновить»);
- без интернета данные только читаются;
- пороги и часть правил приняты как допущения и ждут подтверждения заказчика.
