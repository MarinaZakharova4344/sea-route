# Расчёты по перевозке

Код: [src/lib/metrics.ts](../src/lib/metrics.ts). Тесты: [src/lib/metrics.test.ts](../src/lib/metrics.test.ts) и [src/lib/recalc.test.ts](../src/lib/recalc.test.ts).
Результат сохраняется в таблицу `shipment_metrics` и обновляется по расписанию или по кнопке; время обновления показывается как «данные на HH:MM».

## Показатели

| Показатель | Как считается |
|---|---|
| Доход (`revenue`) | Сумма строк дохода. Для каждой строки берётся факт, если его нет, то план |
| Расход (`cost`) | То же для строк расходов |
| Маржа (`margin`) | Доход − расход |
| Предварительно (`is_preliminary`) | «Да», пока перевозка не закрыта финансово **или** по какой-либо строке нет факта. У отменённой перевозки: «да», только если по строке нет факта |
| Дата результата (`result_date`) | Фактическая дата прибытия. Пока груз не доставлен, пусто. У отменённой: дата последнего обновления |
| Задержка (`delay_days`) | Прибыл: фактическая дата − плановая (не меньше 0). Не прибыл (забронирован или в пути): сегодня − плановая дата, если она прошла |
| Перерасход (`overrun_pct`) | По расходам, где известен факт: (факт − план) / план × 100. Внеплановые расходы (план 0) входят в факт целиком. Расходы без факта не учитываются |
| Просроченная оплата | Есть строка с фактом, не оплаченная полностью, срок оплаты которой прошёл |
| Не обновлялась (`stale_days`) | Сегодня − дата последнего обновления. Только для перевозок в работе (забронирована, в пути, прибыла) |
| Неполные данные | Нет: клиента, направления, груза, плановых дат отправления и прибытия, контейнеров; для перевозок в пути и прибывших ещё и номеров контейнеров |

## Причины «Требует внимания» (экран «Сегодня»)

Перевозка попадает в список, если выполняется хотя бы одно условие. Пороги берутся из таблицы `settings` и могут меняться.

| Причина | Условие | Порог по умолчанию |
|---|---|---|
| Опоздание | Забронирована или в пути, задержка > порога | 2 дня |
| Перерасход | Перевозка не закрыта финансово, не черновик и не отменена, перерасход > порога | 10 % |
| Просрочена оплата | Есть просроченная оплата (не для черновиков) | — |
| Не заполнено | Не черновик и не отменена, есть недостающие поля | — |
| Не обновлялась | Перевозка в работе, дней без обновления > порога | 5 дней |

Сравнение всегда строгое («больше»): ровно 2 дня или ровно 10 % причиной не считаются.

Задержка у уже прибывшей перевозки сохраняется в показателях (для сравнения клиентов и направлений), но причиной внимания не является: вмешиваться уже поздно. По той же причине перерасход у закрытой финансово перевозки внимания не требует.

## Пример на конкретных числах

Доход 10 000. Фрахт: план 6 000, факт 6 200. Терминал: план 1 000, факта ещё нет.

| Этап | Расход | Маржа | Статус |
|---|---|---|---|
| Груз прибыл | 6 200 + 1 000 = 7 200 | 2 800 | предварительно |
| Пришёл факт по терминалу 1 000, добавлено хранение 500 | 6 200 + 1 000 + 500 = 7 700 | 2 300 | предварительно |
| Менеджер нажал «Закрыть финансово» | 7 700 | 2 300 | окончательно |

Эти три шага проверяются тестами.

## Известные ограничения
- Суммы целые, в рублях; НДС и курсовые разницы не учитываются.
- Общие расходы компании в маржу не входят (она «валовая», по перевозкам).
- Пересчёт идёт целиком по всем перевозкам: для десятков и сотен записей это быстро, для больших объёмов потребовался бы инкрементальный пересчёт.
- Пороги и правила ждут окончательного подтверждения заказчика.
