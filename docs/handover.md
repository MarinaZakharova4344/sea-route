## Как проверить за 10 минут

1. Запуск: пять команд из [README](../README.md#быстрый-запуск), затем `http://localhost:3000`.
2. Пройти «Сценарий 1» из [demo-scenario.md](demo-scenario.md): менеджер вносит счёт больше сметы, руководитель нажимает «Обновить» и по причине доходит до перевозки.
3. Закрыть перевозку финансово, открыть заново, добавить расход (сценарий 3): на «Динамике» появится «пересчитано задним числом».
4. Запустить `npm test`.
5. После проверки вернуть чистые данные: `npm run db:seed`.

## Решения, принятые самостоятельно

Полный список с вариантами, причинами и проверкой: [decision-log.md](decision-log.md), разделы «Проблемы, найденные и решённые самостоятельно» и «Решения, принятые при доработке после согласования». Главное:

- **Менеджер сводную аналитику не видит.** В ТЗ она названа «аналитикой руководителя»; заказчик отдельно не отвечал. Меняется одной проверкой прав.
- **Менеджер правит любые перевозки** (согласовано). Защита от злоупотреблений: каждая правка записывается, руководитель видит «кто, когда, что было → стало».
- **Оплаты клиентов считаются по дате прихода денег, маржа по дате доставки** (согласовано).
- **Три сложных случая и найденная ошибка** (частичная оплата без даты): [edge-cases.md](edge-cases.md).
- **Найденные и исправленные проблемы**: вход «не держался» в рабочей версии по `http://` (флаг Secure у куки), падение установки на чистом компьютере (`.npmrc`), потеря события установки, возврат на прежнее место списка, фильтры менеджера.

## Что нужно знать о запуске и границах первой версии

- **Установка на телефон требует https.** По `localhost` на компьютере (Chrome, Edge) установка проверена. Яндекс.Браузер устанавливает приложения через собственное меню, кнопка «Установить» там только подсказывает. На телефоне по адресу `http://192.168…` браузеры установку не предлагают; для показа на телефоне нужен защищённый адрес (например, временный туннель). Размещение на сервере в ТЗ не требуется.
- **Одна дата оплаты у строки.** При оплате частями вся сумма относится к дате последней оплаты; журнала отдельных платежей нет.
- **Задержка аналитики до 5 минут**, или сразу по кнопке «Обновить».
- **Нет офлайн-правок**: без связи данные только читаются (в ТЗ не требуются).
- **Режим разработки** (`npm run dev`) на iPhone может показывать красную плашку разработчика; в рабочей версии (`npm run build`, `npm start`) её нет. Не запускайте `build`, пока работает `dev`.

Полный список ограничений: [calculations.md](calculations.md#5-известные-ограничения).

## Что можно поменять по вашему решению

| Если нужно | Что изменится |
|---|---|
| Менеджер должен видеть сводную аналитику | Одна проверка прав на сервере и пункт меню |
| Менеджер правит только свои перевозки | Проверка прав на запись, остальное без изменений |
| Точный учёт частичных платежей | Отдельная таблица платежей и экран |
| Размещение для телефона | Хостинг с https и постоянным диском под базу |
